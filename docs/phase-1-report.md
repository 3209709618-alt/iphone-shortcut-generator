# 第一阶段技术验证报告

> 本文保留原有在线后台方案的阶段记录。用户随后要求先开发无后台的静态网站，当前进展请看 [静态版报告](static-site-report.md)。以下云部署门槛不再阻止静态界面开发；签名和实机导入仍未通过。

核对日期：**2026-10-15（Asia/Shanghai）**。结论：**阶段门槛未通过，暂不扩大网站实现**。

## 已证实的阻塞

### 1. CloudBase 免费云函数不能作为当前长任务方案的可靠执行环境

[官方资源点价格文档](https://cloud.tencent.com/document/product/876/127357) 的上海套餐表明确列出：

- 免费体验版：3000 资源点/月。
- 云函数超时时间：**3s，不支持修改**；内存：**256M，不支持修改**。
- 个人版：当前展示 **19.9 元/月（限时优惠）**、40,000 资源点/月，函数超时可配置至最大 900s；实际购买价及续费价以订单页为准。
- 免费环境单次可续期 6 个月，到期前 1 个月内手动续期，不自动续费；每个云开发账号使用兑换码创建免费体验环境，有已有免费环境等资格限制。
- 免费体验版不支持加购资源包和按量付费，不能把免费点数写成永久免费承诺。

[官方能力说明](https://cloud.tencent.com/document/product/876/120713) 亦明确指出默认 3 秒/256 MB 无法满足 AI 推理等复杂需求。

影响：AI 生成、运行时 AI 和第三方签名均含不可控的外部请求延迟。即使快速的本地编译低于 3 秒，也不能据此认定端到端处理可稳定在 3 秒内结束。保存任务状态、轮询进度不解除执行上限；将工作放在函数返回后的后台线程也不构成可靠执行方案。

这不是“所有免费平台都不可能”的结论；改用云托管或其他平台需要重新核实额度、执行时间、后台任务生命周期、私有持久化及大陆手机访问。

### 2. 默认域名与正式长期使用要求冲突

[CloudBase 默认域名访问限制及中间页](https://docs.cloudbase.net/service/alias) 当前说明：

> 建议仅在测试环境使用云开发「默认域名」。在生产环境使用默认域名可能因流量触发风控而被关停，请务必配置「自定义域名」。

页面还写明默认域名仅建议用于开发测试、不得用于正式生产环境或大规模分发；浏览器导航会展示访问提示中间页，确认后使用 Cookie 暂免重复提示，其他请求会添加 `Content-Disposition: attachment`。移除中间页需自定义域名，自定义域名需 ICP 备案。

影响：不能将平台默认地址承诺为符合本任务的正式长期网址；Safari 下载跳转、资源请求、运行时 API 和 Cookie 行为也需实际验证。购买个人版本身不消除默认域名限制。用户当前没有域名，涉及购买和备案的方案需要另行决定。

### 3. HubSign 尚未通过使用权限和服务验证

- [Cherri v2.3.0 README](https://github.com/electrikmilk/cherri/blob/d2072c62ea708e7727099fab94fa28b0bcec747b/README.md) 指向 RoutineHub membership。
- [固定版本 signing.go](https://github.com/electrikmilk/cherri/blob/d2072c62ea708e7727099fab94fa28b0bcec747b/signing.go) 使用 `https://hubsign.routinehub.services/sign`，JSON 字段为 `shortcutName` 和 XML 字符串 `shortcut`。
- 本次读取 `https://routinehub.co/membership` 得到 HTTP 403 / Cloudflare 验证页；服务根地址的只读请求也返回 403。普通浏览器工具在创建页面时失败，因此未能通过浏览器核实条款。
- **这不能证明 `/sign` 永久不可用，也不能证明服务免费或允许网站集成。** 本次没有 POST 到签名接口，没有绕过访问拦截，没有发送文件。

影响：服务使用权限、免费额度、限频、数据保留政策及当前可用性均待核实。签名前只允许合成数据或不含个人内容的编译文件；供应商密钥、真实短信、账目及运行授权码不得发送给签名服务。

## 已通过的本地技术检查

编译器：Cherri **v2.3.0**，固定 commit `d2072c62ea708e7727099fab94fa28b0bcec747b`。

- Windows：从固定版本源码构建；Go 1.26.4；编译器 SHA-256 `08ef57c77cc8008d0634b646e848f52d42d4e8b625784beb94e38c80bd34ff47`。
- Linux：WSL2 / 本机已安装 Linux 环境，运行官方 Linux x86_64 发布包；包 SHA-256 与 GitHub 发布值 `7ab2c384b7b26e7c72a30a8dfa56f89dae12c4068b7951bc1e3193f3698edbe9` 一致。
- Linux 编译器本身 SHA-256 `e36d276e01c2807f34a40bef5e208aa18d7f70770c2fd787848e7fc2084aa42e`。

- Python 标准库 `plistlib` 成功解析实际产物；Windows 与 Linux 的四份输出均逐字节一致。

原始本机报告：`.local/checks/compiler-l0osw1sh/report.json`（Windows）、`.local/checks/compiler-_75laclf/report.json`（Linux）。这些路径是本次记录，重新执行会创建新目录。文件不进入仓库。

发现并修正：未指定输入类型时，Cherri 默认输入类型数组顺序不稳定；本次全部 fixture 显式声明 `#define inputs text`。`--derive-uuids` 单独不足以保证所有输出稳定。**上述确定性仅覆盖四份探针，不能泛化成完整编译引擎已经验证。**

执行了 7 项单元测试：合法 XML/binary plist、无参数动作、HTML/JSON/空内容/伪造头/无动作等异常产物拒绝、体积限制、禁止任意源文件、编译超时传播、禁止开启签名。全部通过。

这些检查没有验证签名真实性。`AEA1` 文件头只能作为格式筛选线索，不能独立证明签名有效；任何将来的已签名下载入口必须以完整签名处理及实机导入验证为依据。

3. 在选定托管环境实测 Node LTS、编译器、模型请求和持久化任务；记录大陆手机网络与真实 iOS 版本。
4. 先通过关键 iPhone 能力验证，再按任务书实现基础功能、生成安装及 Apple 风格界面。
